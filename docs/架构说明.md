# 架构说明

## 1. 总览

```
┌──────────────────────────┐        HTTP + X-API-Key        ┌─────────────────────────────┐
│  Android App (Kotlin)     │  ───────────────────────────▶  │  电脑端服务 (FastAPI)         │
│  Compose UI               │   POST /api/sync (增量双向)     │  SQLite: tasks / devices     │
│  TaskStore (JSON 文件)     │  ◀───────────────────────────  │  静态控制台 static/index.html │
│  AlarmManager + 通知       │                                └─────────────────────────────┘
└──────────────────────────┘                                              ▲
                                                                            │ 浏览器
                                                                      控制台（同一套 API）
```

- **手机是执行端**：任务的增删改、提醒的排期和弹出都在本地完成，不依赖网络。
- **电脑是观察与管理端**：拿着手机同步上来的数据做汇总展示，也可以直接改。
- **没有云端**：所有数据只在手机文件和电脑 SQLite 里。

## 2. 手机端分层

```
data/      Task 模型 · Repeat 规则 · TaskOps 纯函数 · TaskStore 持久化 · SyncClient · AppSettings
alarm/     ReminderScheduler（排期）· ReminderReceiver（弹通知）
           NotificationActionReceiver（通知按钮）· TaskWidget（桌面小组件）· BootReceiver
ui/        Theme · Components · Screens（今天/本周/全部/设置）· Sheets（快速添加/详情）· AppRoot
```

设计原则：

1. **所有写操作走 `TaskOps` 纯函数**，这样「App 里点完成」和「通知栏点完成」是同一套逻辑，
   重复任务的派生也只有一个实现。
2. **UI 只读状态**，`TaskViewModel` 负责持久化 + 重排闹钟 + 触发同步。
3. **提醒不依赖同步**：即使服务端挂掉，闹钟照旧。

## 3. 数据模型

```kotlin
Task(
  id, title, notes,
  dueAt: Long?,        // 到期时间（epoch ms）
  remindAt: Long?,     // 提醒时间，可独立于到期时间
  priority: 1|2|3,
  repeatRule: ""|daily|weekdays|weekly|monthly,
  done, deleted, updatedAt, createdAt
)
```

`deleted` 是软删除墓碑，用于让删除动作也能参与同步。

## 4. 提醒链路

```
用户设置提醒
   └─▶ ReminderScheduler.schedule()
         setExactAndAllowWhileIdle(RTC_WAKEUP, remindAt, PendingIntent)
              │  （没有精确闹钟权限时退化为 setAndAllowWhileIdle）
              ▼
         ReminderReceiver.onReceive()
              └─▶ NotificationCompat（通知渠道 "reminders"）
                     ├─ 点正文 → MainActivity + open_task_id → 打开详情
                     ├─ 点「完成」→ NotificationActionReceiver → TaskOps.complete → 重排 + 更新小组件
                     └─ 点「10 分钟后」→ TaskOps.snooze(now+10min) → 重排
```

开机 / 覆盖安装后由 `BootReceiver` 重新排期，避免重启丢提醒。

## 5. 同步协议

`POST /api/sync`

```json
{
  "device_id": "uuid",
  "since": 1793243710000,
  "tasks": [ { "id": "...", "title": "...", "due_at": 0, "remind_at": 0,
               "priority": 2, "repeat_rule": "daily",
               "done": false, "deleted": false, "updated_at": 0 } ]
}
```

服务端按 `id` 合并：不存在则插入；`updated_at` **严格更大**才覆盖；否则忽略。
返回 `updated_at > since` 的全部任务（含墓碑）。

冲突策略是 last-write-wins，比较的是客户端时钟；同一时刻以服务端为准。
个人单设备场景下冲突概率极低，代价是实现足够简单、可预期。

## 6. 新增字段要改哪些地方

以 `repeat_rule` 为例，一共五处：

1. `app/data/Task.kt` — 字段 + `toJson/fromJson`
2. `app/data/TaskOps.kt` / `Repeat.kt` — 业务规则
3. `app/ui/Sheets.kt` — 录入界面
4. `server/store.py` — 建表 + `MIGRATIONS`（老库补列）
5. `server/service.py` — `task_to_json` / `_normalise_sync_task` / `create_task` / `patch_task`

## 7. 测试策略

- **Android**：JVM 单元测试覆盖纯逻辑（重复规则边界、完成后派生、删除恢复、稍后提醒），
  `./gradlew :app:testReleaseUnitTest`。
- **服务端**：`unittest` 覆盖合并语义、增量、墓碑、统计口径、鉴权与 404，无需联网。
- **CI**：`.github/workflows/ci.yml` 在 push / PR 时同时跑两端。
- **手工**：安装到真机，用「60 秒后测试提醒」验证闹钟链路。
